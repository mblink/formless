# AGENTS.md

Guidance for AI coding agents (Claude Code, Codex, Cursor and others) working in this repository. `CLAUDE.md` imports this file.

## What this is

formless is a generic programming library (HLists, records, tagged types) for Scala 2.13 and Scala 3, published as `com.bondlink::formless` to BondLink's S3 Maven repo. On Scala 2.13 it is mostly a thin layer over shapeless 2; on Scala 3 it reimplements `HList` and the type classes natively using match types, `compiletime` ops and a few quoted macros.

## Build & test

sbt with `sbt-projectmatrix`. There is no root aggregate worth targeting directly — pick the matrix project:

| Project | Platform / Scala |
|---|---|
| `core` | JVM, 2.13 |
| `core3` | JVM, Scala 3 LTS (3.3.x, the default `scalaVersion`) |
| `coreNext3` | JVM, Scala 3 Next (3.8.x) — only defined when sbt runs on Java ≥ 17 |
| `coreJS`, `coreJS3` | Scala.js |
| `coreNative`, `coreNative3` | Scala Native |
| `docs3` | mdoc docs project |

Common commands:

- `sbt core3/test` / `sbt core/test` — test one Scala version on the JVM (fastest loop). Changes usually need checking on **both** 2.13 and 3.
- `sbt 'core3/testOnly formless.record.LookupTests'` — single suite (munit); scalacheck `Properties` suites (e.g. `formless.hlist.SelectorTest`) run the same way.
- `sbt test` — everything, all platforms (what CI runs on Java 8/11/17/21/25).
- `sbt mimaReportBinaryIssues` — binary-compat check (CI, Java 25 only); disabled until 0.9.0, which breaks binary compatibility, is published.
- `sbt mdoc` — regenerates the root `README.md` from `docs/README.md`. **Edit `docs/README.md`, never the root README** — it's overwritten. Variables like `@VERSION@` are substituted from `build.sbt`.
- CI workflow (`.github/workflows/ci.yml`) is generated by sbt-github-actions: change `build.sbt` and run `sbt githubWorkflowGenerate` rather than editing the YAML (CI runs `githubWorkflowCheck`).

`sbt-tpolecat` is on, so warnings are strict; `-no-indent` is set for Scala 3 (use braces).

## Source layout

Version-specific source directories under `core/src/{main,test}`:

- `scala/` — shared by both versions (package objects, a few ops like `SelectMany`, `PatchAux`).
- `scala-2.13/` — Scala 2 code. `formless.hlist.HListPackageCompat` aliases shapeless's `HList`, `::`, `HNil` and ops; formless type classes there mostly wrap `shapeless.ops.*`. Int-literal indices are bridged to shapeless `Nat` via `IntToNat`/`NatToInt`.
- `scala-3/` — the native Scala 3 implementation. Each type class lives in its own file in `formless/hlist` or `formless/record`; syntax is in `HListOps.scala` / `RecordOps.scala`.
- `test/scala-2` vs `test/scala-3` — differing `illTyped` helpers (Scala 3 uses `compiletime.testing.typeChecks`). `*TestsCompat.scala` hold version-specific tests alongside the shared `HListTests`/`RecordTests`.

The public API is meant to be identical across versions, so a new op normally needs a Scala 3 implementation, a Scala 2.13 implementation (usually delegating to shapeless), and shared tests.

## Scala 3 record field lookup

Record ops (`Selector`, `Updater`, `Modifier`, `Remover`, `LacksKey`) and HList ops looked up by element type (`Remove`, `Replacer`, `Modifier`, the splits, `NotContains`) on Scala 3 share one quoted macro walk, `formless.record.Lookup.Walk` in `core/src/main/scala-3/formless/record/Lookup.scala`. `FieldOp` (records) and `formless.hlist.ElemOp` build each op's result types directly; `FieldAbsent` proves absence. The walk must stay sound for abstract tails, intersections, unions and `HNil` subtypes: a field is only proven absent when no element could possibly match. Every macro entry point goes through `Lookup.guarded`, so nothing may crash the compiler. `LookupTests`, `ElemOpTests` and `LookupCrashTests` cover these edge cases. A lookup that fails reports the type class's `@implicitNotFound` message, since the compiler drops a macro's own error inside an implicit search; keep those messages accurate when changing what a lookup accepts, and summon evidence in syntax methods as `TC[A, B] { type Out = O }` rather than through an `Aux` alias, which the message can't see through.

## Generated tests

`project/SourceGenerator.scala` generates scalacheck suites at test-compile time (selector/updater/modifier/renamer/remover over records of up to 12 fields, written to `target/.../src_managed/test/generated`). Edit the generator, not the generated output.

## Code style

Follow `.claude/skills/scala-code-style/SKILL.md`. In short:

- Work compiler-first: change the types, read every error, and fix each one completely, never by silencing it.
- Model alternatives as ADTs, never as strings, sentinels or `null` (use `Option`), and match exhaustively.
- Prefer immutable values. Mutation is allowed only locally, with a comment, where performance needs it.
- Validate input once at a boundary, such as a macro's entry point, and trust the types past it.
- Return failures as values (`Either` with a sealed error ADT) instead of throwing or aborting from deep inside. Capture exceptions with `Try` or `scala.util.control.Exception`, not a literal `try`/`catch`.
- Remove duplicated knowledge, not merely similar code.
- Pin every compile-time guard with a `typeCheckErrors` test.
- Claim nothing is done without fresh test output.
